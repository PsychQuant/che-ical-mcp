# Tool annotation policy

Read tools explicitly set readOnlyHint=true and destructiveHint=false. Creation tools that only add new items set both false. Tools that delete, replace, clear, complete, reopen, undo, redo or optionally move existing data set destructiveHint=true. The hint applies to the whole tool, including calls that do not remove anything. ToolAnnotationTests enumerates every tool so additions require a policy decision.

copy_event with delete_original=true and move_events_batch record source deletion for undo. Undo restores a standalone source occurrence and leaves the target copy in place; it does not clone the recurring series. Copying preserves the tool’s supported property subset, not attendees or a full series. If saving the copy succeeds but source deletion fails, the copy can remain; inspect the target calendar before retrying. Failed deletions do not record source restoration.

Restoration uses the original calendar or reminder list identifier, not its title. Two accounts can contain the same calendar or list name, and a renamed calendar or list keeps its identifier. If the recorded calendar or list no longer resolves, undo fails and retains the record rather than restoring into another account; for a reminder list, the error names the reminder (not the list or its account, #290), and for an event's calendar (the undo of `delete_event`, `update_event` or a move) it names the event (not the calendar or its account, #269); both say how to give up the undo with discard_id. An event undo judges its calendar missing only after Calendar access is checked and a stale view is read again. Giving up cannot be reversed: for a delete-undo, the deleted reminder or event can no longer be recreated through undo afterwards; for an update-undo, the reminder or event stays as it is; for a move-undo, the event stays in the calendar it was moved to. Until the entry is undone or given up, older undo entries stay blocked behind it.
